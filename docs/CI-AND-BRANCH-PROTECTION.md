# CI and solo-owner main protection — proposal only

The local workflow uses package.json engines (Node >=24 <25), Ubuntu 24.04, immutable official action release hashes, read-only contents permission, no persisted checkout credentials and no hosted secrets. It runs npm ci, npm run check (lint/types/build), npm test (disposable databases) and production-only audit at low severity or greater. No fixture scripts, deployments, pull_request_target, caches, cloud tokens or privileged environments. Workflow source: .github/workflows/project-ci.yml. Official action references: https://github.com/actions/checkout/releases/tag/v5.0.0 and https://github.com/actions/setup-node/releases/tag/v6.0.0. Future action updates require reviewed hash changes.

Linux x64 embedded PostgreSQL is present in the lockfile; the tests initialize a user-owned cluster on loopback with an ephemeral port, and stop/remove it after tests. A successful real GitHub Ubuntu run remains unverified. Do not make its status mandatory until an approved PR run passes. Draft creation does not activate Actions. npm audit is network dependent and can fail closed on registry outages. Development-chain advisories remain outside the production audit gate and must still be tracked.

Proposed main rule: require pull requests and the observed Verify project status from Project CI, require branch up-to-date and conversations resolved, block branch deletion and force pushes. Required approving reviewers: zero (solo owner cannot approve own PR). No merge queue, signed-commit requirement or code-owner-review requirement proposed. Verify plan eligibility/enforcement before activation. Owner emergency bypass only for PR merges, explicitly selected and documented; no routine direct pushes, no broad bypass for apps. Emergency changes still require local checks and a retrospective PR/evidence. Do not lock the sole owner out before a trial successful PR.

Approval order: review files; separately authorize branch/commit/push and PR creation (push may create a Vercel Preview; keep it credential-free); run CI on the PR; observe exact status name and Linux support; separately approve main rule and narrow bypass; then authorize merge/production release. This document activates nothing. Do not assume GitHub CI gates Vercel's independent Git deployment: main PR protection gates normal source updates, but manual dashboard redeploy/promote remains possible. Do not edit Vercel permissions/configuration without separate approval. Review owner MFA/recovery privately.
